## 日志库复制：EOF / already exists 实测报错修复（同日）

- 飞飞实测：复制多个表全部报 `code: 57, Table ... already exists` + EOF。
- 根因：① `SHOW CREATE TABLE` 产出的 DDL 不带 `IF NOT EXISTS`；CH 连接 EOF 时语句已执行、仅响应读取失败，`doQueryWithRetryContext` 重试同一条非幂等 DDL 必撞 already exists，且失败 ref 不在 created 列表未回滚，目标库残留物理表。② 同名跳过只查了 ClickVisual 元数据，没查物理表存在性。
- 修复（log_library_copy.go）：
  - `makeDDLIdempotent`：rewrite 链路末端给 CREATE TABLE / CREATE MATERIALIZED VIEW 补 `IF NOT EXISTS`（已有则不补，大小写不敏感，非 create 语句原样返回）；attach SQLs 同链路受益。
  - `targetPhysicalTablesExist`：重放前查目标实例 `system.tables WHERE database=目标库 AND name IN (物理表名)`，任一存在即整库跳过（copyOutcomeExists，进 Skipped），不报错。
  - `copyOutcome` 三态（Done/Fixed/Exists）替代原来的 bool 返回。
  - DDL 执行失败回滚时把当前 ref 也加入 created（EOF 场景语句可能已生效，DROP IF EXISTS 幂等兜底）。
- 验证：go build/vet、base 包 10 个复制相关单测全过（新增 TestRewriteLogLibraryCopyDDLIsIdempotent 6 用例）、router 包过。TestSettingUpdate 失败为存量环境依赖（无 config+MySQL），与本次无关。

## 日志库复制：DDL 走 Query 必 EOF 的根因与修复（同日，重要）

- 飞飞换实例组合再测（源=正式用clickhouse，目标=测试用clickhouse/172.16.128.161）：6 个全部失败，错误 EOF；且失败后目标库**又建出了 6 张表**（语句已执行、只是响应读取失败）。
- 根因（探针程序实锤）：clickhouse-go v2.3.0 在 CH 24.3 上，**DDL 走 database/sql Query 必 EOF**（SELECT 正常、DDL 报错能返回、DDL 成功 EOF 且已执行）；走 `Exec` 完全正常。ClickVisual 其他 DDL 路径（建表/删表/建库）全都用 Exec，只有复制流程的 DDL 重放+回滚用了 `DoSQL`（Query）。
- 修复：factory 加可选接口 `DDLExecutor{ExecSQL(sql) error}`，ClickHouseX/Databend 实现；copyLogLibrary 重放与 rollbackCopiedLogLibrary 全部改走 ExecSQL。预检/结构检测是 SELECT，继续走 DoSQL。
- 同时修了一个数据级 bug：回滚 DROP 用的是 `refs[i].Database`（**源库名**）+ targetOp，跨实例复制时会在目标实例上按源库名删表（若目标实例有同名库=误删！）。改为 `targetDatabase.Name`，并抽出纯函数 `rollbackDropSQL` 便于测试（TestRollbackDropSQLUsesTargetDatabase）。
- 验证：探针端到端过（真实 DDL/建/删/预检 SELECT 全 OK）；go build/vet、base 包 14 个单测、router 包过；inquiry 包 3 个失败（Test_adaSelectPart*/TestStandaloneData）为存量，stash 对照确认与本次无关。
- 注意：目标库 test_56linked_new 现有 6 张上次失败重建的残留表，飞飞重测前需清掉（或会被 SkippedLeftover 跳过）。DROP 是高危操作，等他确认。
